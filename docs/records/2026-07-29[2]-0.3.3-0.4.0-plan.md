## 4. Milestone 1 — v0.3.3 (патч)

### P0 — критично

#### 4.1. [B1] `flush()` буферных паблишеров: drain-семантика вместо зависания

- **Проблема:** `flush()` зависает навсегда на простаивающем паблишере
  (`async_publisher_with_buffer.dart:51-54`, `async_publisher_with_buffer_and_param.dart:55-58`).
- **Решение:** ввести флаг `_isProcessing` (батч в обработке). `flush()`:
  - буфер пуст и обработки в полёте нет → вернуть `Future.value()` немедленно;
  - иначе → `_flushCompleter ??= Completer()` и, если буфер непуст и тик ещё не
    запланирован, добавить тик в контроллер.
  Семантика — **drain**: `flush` завершается при полном опустошении очереди, включая логи,
  опубликованные после вызова `flush` (зафиксировать в dartdoc).
- **Совместимость:** патч-безопасно — текущее поведение (вечное зависание) не может быть
  чьим-то рабочим контрактом.
- **Тесты:** flush на свежем паблишере; flush после полного опустошения; flush во время
  обработки батча; flush через `MultiPublisher` со смешанным списком.
- **Критерии приёмки:** `await flush()` завершается во всех перечисленных сценариях;
  существующие тесты зелёные.

#### 4.2. [B5] Обработка ошибок `handle`: параметр `onError`

- **Проблема:** исключение в `handle` → uncaught zone error (падение изолята в чистом
  Dart), потеря `retryBuffer`, зависший `_flushCompleter` (все 4 файла async-паблишеров).
- **Решение:**
  - опциональный параметр конструктора `void Function(Object error, StackTrace stackTrace)?
    onError` у всех четырёх баз (сигнатура — см. решение Р2, раздел 7);
  - обёртка `handle` в try/catch **внутри** конвейера (`_handleData` / `asyncMap`-коллбек),
    чтобы при ошибке всегда выполнялись возврат `retryBuffer` в очередь и `_next`;
  - при `onError == null` — `Zone.current.handleUncaughtError(...)`, как у `MultiPublisher`;
  - подписке добавить `onError`-хендлер как последний рубеж.
- **Совместимость:** аддитивно; дефолтное поведение для необработанных ошибок совпадает с
  текущим (uncaught в зоне), но пайплайн больше не встаёт.
- **Тесты:** throw в `handle` → `onError` вызван, следующий лог обработан, `retryBuffer` не
  потерян, `flush` завершается; вариант без `onError` → ошибка в зоне, пайплайн жив.
- **Критерии приёмки:** ни один сценарий с throw в `handle` не приводит к потере логов из
  `retryBuffer`, остановке очереди или зависанию `flush`.

#### 4.3. [B2] `TypedLazy`: `.resolved` после `.value` не возвращает сентинел

- **Проблема:** приватный `_NoData` утекает через публичный `resolved` (`lazy.dart:78-88`).
- **Решение** (в ходе реализации усилено относительно первоначального «переопределить
  `resolved` в `TypedLazy`»): устранить сентинел `_NoData` целиком. Вместо трёх полей
  с магическими значениями — одно поле-слот, проходящее фазы «источник → разрешено →
  сконвертировано» под явными булевыми флагами (`_isResolved`, `_isConverted`). После
  конверсии слот хранит итоговое значение, поэтому семантика Р3 («`resolved` после
  `value` возвращает сконвертированное значение») выполняется без переопределения
  геттера — утечка сентинела исключена структурно. Контракт зафиксирован в dartdoc.
  Память: оригинал и конверсия не удерживаются одновременно; число полей не выросло.
- **Совместимость:** патч-безопасно — внутренний рефакторинг, публичный API и
  поведение не меняются.
- **Тесты:** `value` → `resolved` == value; `resolved` → `value`; ни в одной
  последовательности наружу не выходит объект с `toString() == '<no data>'`.
- **Критерии приёмки:** класса-сентинела нет в коде; `test/lazy_test.dart` проходит
  без правок.

#### 4.4. [B3] Порядок веток `switch` по `FutureOr<Out>`

- **Проблема:** ветка `final Out out` первой матчит `Future` при `Out = Object?`/`dynamic`
  (`async_publisher.dart:126-129` и 3 аналога).
- **Решение:** во всех 4 местах поставить `final Future<Out> future` первой веткой.
  Проверено: для конкретных `Out` (включая экзотический `Out = Future<X>`) поведение не
  меняется — прямое значение `Future<X>` не матчится на `Future<Future<X>>` и корректно
  уходит во вторую ветку. Меняется только случай `Out = Object?/dynamic/FutureOr`, где
  старое поведение и было багом. Отметить в CHANGELOG.
- **Совместимость:** патч-безопасно (изменение только для багованных инстанциаций).
- **Тесты:** `AsyncFormatter<Log, Object?>` с async `format` → `output` получает значение,
  а не `Future`; регресс для конкретного типа `Out = String`.
- **Критерии приёмки:** `output` никогда не получает незавершённый `Future` результата
  `format`.

### P1 — в этот же релиз

#### 4.5. [B4] `remainingLogs` после завершения `format`

- **Проблема:** список считается до завершения асинхронного `format` + O(n·m)
  (`async_publisher_with_buffer.dart:157-166`, `..._and_param.dart:199-205`).
- **Решение:** вычислять `remainingLogs` после завершения `format` (для async-ветки —
  внутри `.then`); фильтровать через identity-`Set` по содержимому `retryBuffer`
  (O(n + m)).
- **Тесты:** async `format` добавляет в `retryBuffer` внутри `await` → `output` получает
  список без этих логов.
- **Критерии приёмки:** `remainingLogs` всегда согласован с итоговым `retryBuffer`
  на момент вызова `output`.

#### 4.6. [B7] Валидация `name` и корректный `shortName`

- **Проблема:** `assert` + `name[0]` → `RangeError` в release, суррогаты для не-BMP
  (`custom_level_logger.dart:62-63`).
- **Решение:** `ArgumentError.value` при пустом имени (вместо assert; см. решение Р5);
  `shortName` по умолчанию — `String.fromCharCodes(name.runes.take(1))`.
- **Совместимость:** тип ошибки для заведомо некорректного входа меняется
  (RangeError → ArgumentError) — допустимо в патче.
- **Тесты:** пустое имя → `ArgumentError`; имя с эмодзи → валидный односимвольный
  `shortName`.

#### 4.7. [B6] Устойчивая пропагация пер-уровневого паблишера

- **Проблема:** `this[level]` в рекурсии бросает `StateError` посреди обхода
  (`custom_logger.dart:163-175`).
- **Решение:** в рекурсивной ветке `_setLevelPublisher` обращаться к
  `_levelLoggers[level]` и молча пропускать саблогеры без такого уровня (симметрично
  логике `CustomLogger.sub:64-69`). Прямой вызов сеттера у уровня, которого нет, — как и
  раньше, `StateError` (через `operator []`).
- **Тесты:** искусственная иерархия с несовпадающим набором уровней → установка паблишера
  у родителя не бросает и обновляет всех, у кого уровень есть.

#### 4.8. [B9] Специфицировать жизненный цикл `close()`

- **Проблема:** `flush` после `close` воскрешает паблишер; `publish` после `close`
  в буферных вариантах молчит (`async_publisher.dart:51-60` и аналоги).
- **Решение:** добавить `bool get isClosed`; контракт: `publish` после `close` →
  `StateError` (во всех вариантах, включая буферные при непустом буфере); `flush` после
  `close` → немедленно завершённый `Future` (идемпотентность — важно для
  `MultiPublisher.flush` по смешанному списку); повторный `close` — no-op.
- **Совместимость:** «воскрешение» после close — недокументированное поведение; фикс
  патч-допустим. `StateError` для буферного `publish`-после-close — ужесточение, отметить
  в CHANGELOG.
- **Тесты:** матрица `publish`/`flush`/`close` × «до/после close» для всех 4 баз.

#### 4.9. [M1] Убрать `Finalizer`, чистить weak-ссылки лениво

- **Проблема:** финализатор строго удерживает родителя, O(n) коллбеки, неограниченный рост
  `_subloggers` (`custom_logger.dart:32-34,182-185`).
- **Решение:** удалить статический `Finalizer`; мёртвые `WeakReference` чистить лениво —
  `removeWhere((r) => r.target == null)` при каждом обходе `_subloggers`
  (`set level`, `set publisher`, `_setLevelPublisher`) и в `registerSublogger`.
  Добавить `@visibleForTesting`-хук принудительной чистки для детерминированных тестов.
- **Совместимость:** патч-безопасно — `Finalizer` не является наблюдаемым API; авточистка
  сохраняется (README-обещание «не нужно dispose» остаётся в силе).
- **Тесты:** после зануления weak-target (через тестовый хук) обходы не считают мёртвые
  ссылки; `subLoggersCount` уменьшается после чистки.

#### 4.10. [M2] Хранить и отменять `StreamSubscription`

- **Проблема:** подписки `_listen` теряются (4 места).
- **Решение:** сохранять подписку в поле; в `close()` — `await cancel()` после закрытия
  контроллера; в `flush()` (`AsyncPublisherBase`, param-вариант) — корректно завершать
  старую подписку перед пересозданием.
- **Тесты:** после `close()` обработчик не вызывается; нет незакрытых ресурсов.

#### 4.11. [D4] Дедупликация внутреннего кода async-паблишеров

- **Проблема:** `_AsyncParamPublisher` дважды (`..._with_param.dart:72`,
  `..._buffer_and_param.dart:100`); `_handleData`/`_next` продублированы между буферными
  файлами.
- **Решение:** вынести адаптер и общий буферный конвейер в файл
  `lib/src/async_publishers/internal/` (не экспортируется в barrel). Выполнять **после**
  фиксов 4.1/4.2 под зелёными регресс-тестами.
- **Совместимость:** приватный рефакторинг, публичный API не меняется.
- **Критерии приёмки:** ни одного дословно продублированного приватного класса/метода;
  все тесты зелёные.

#### 4.12. [D6] Унификация импортов

- **Проблема:** абсолютные self-импорты, self-import barrel-файла, относительные — вперемешку.
- **Решение:** внутри `lib/` — только относительные импорты; убрать импорты

- **Критерии приёмки:** `dart analyze` — 0 issues с включённым правилом.

#### 4.13. [D8] Согласовать `fallbackValue` у `LazyString.resolved`

- **Проблема:** `''` против `'null'` (`lazy.dart:101,103-105`).
- **Решение:** `LazyString.resolved(super.resolved, [this.fallbackValue = 'null'])` —
  единый дефолт с основным конструктором.
- **Совместимость:** формально меняет результат для `LazyString.resolved(null)` — но
  конверсия для уже-резолвнутого null-значения типа `String` недостижима на практике

## 5. Milestone 2 — v0.4.0 (breaking)

#### 5.1. [B8] Ошибки `MultiPublisher.flush` через `onError`

- **Решение:** пер-паблишерный catch в `flush`; при заданном `onError` ошибки идут в него,
  `flush` завершается успешно; при `onError == null` — прежнее поведение
  (`ParallelWaitError`). См. решение Р7.
- **Почему breaking:** меняется наблюдаемое поведение для кода, ловившего
  `ParallelWaitError` при заданном `onError`.
- **Тесты:** обновить `multi_publisher_test.dart:95` + новые кейсы.

#### 5.2. [D3] Интерфейсы жизненного цикла

- **Решение:** ввести `Closable` (`Future<void> close()`; имя финализировать) рядом с
  `HasFlush`/`Flushable`; все async-базы реализуют оба; param-базы получают общий
  интерфейс «flushable/closable источник»; `MultiPublisher.close()` — каскадно по
  `whereType<Closable>()`.
- **Почему breaking:** реструктуризация иерархии интерфейсов, новые обязательные члены для
  сторонних реализаций.

#### 5.3. [D2] `CustomLevelLogger` → `abstract base class`

Запрет внешнего `implements`. Breaking формально (для тех, кто имплементил), по факту —
выравнивание с задумкой.

#### 5.4. [D5] `MultiPublisher` копирует список

`_publishers = List.of(publishers)`. Breaking для сценария «живого» списка (см. Р8).

#### 5.5. [D1, финал] `HasFlush` → `Flushable`

Переименование; в 0.3.3 заранее добавить `typedef HasFlush = Flushable` с `@Deprecated` —
либо наоборот, ввести `Flushable` в 0.3.3 как основной тип, оставив `HasFlush`
deprecated-алиасом (предпочтительно).

#### 5.6. [M3, опционально] Отключаемый захват зоны

Базовое решение Р6 — поле остаётся (4.17), пункт исполняется **только по фактической
необходимости**: если удержание зоны буферными паблишерами проявится как проблема на
практике, в 0.4.0 сделать захват опциональным (`Zone? zone` без дефолта `Zone.current` —
breaking). Отдельного решения сейчас не требует.

  `child.level = child.level`;
- (опционально) `unregisterLevel`.
  Аддитивно, но логично в 0.4.0 вместе с 5.2.

#### 5.8. [T2, финал] Включить `public_member_api_docs`

Включить линт, добить оставшиеся пробелы. Критерий: `dart analyze` — 0 issues.

## 7. Принятые решения

Все решения зафиксированы автором 2026-07-29; исполнитель следует им без дополнительных
согласований.

| № | Вопрос | Принятое решение |
|---|---|---|
| Р1 | Семантика `flush` буферных паблишеров (4.1) | **Drain**: ждать полного опустошения очереди, включая логи, опубликованные после вызова `flush` |
| Р2 | Сигнатура `onError` (4.2) | `void Function(Object error, StackTrace stackTrace)` — без третьего аргумента (паблишер один; для батчей `List<Log>` не передаётся) |
| Р3 | `.resolved` после `.value` (4.3) | Возвращать **сконвертированное** значение (оригинал и конверсия не удерживаются одновременно) |
| Р4 | Порядок веток switch (4.4) | `Future<Out>` первым; пометка в CHANGELOG для `Out = Object?` |
| Р5 | Пустое `name` (4.6) | `ArgumentError` в любом режиме сборки (вместо assert) |
| Р6 | Судьба `CustomLog.zone` (4.17) | **Вариант «в»**: поле остаётся, библиотека его не использует; документируется как поле для пользовательских форматтеров (zone-locals через `log.zone[...]`, выполнение в зоне лога через `log.zone.run(...)` в своём `handle`). Deprecation не выполняется |
| Р7 | Ошибки `MultiPublisher.flush` (5.1) | Маршрутизировать в `onError` в 0.4.0; при `onError == null` — прежний `ParallelWaitError` |
| Р8 | Список в `MultiPublisher` (5.4) | Копировать `List.of` в 0.4.0 |
| Р9 | `onError` в патче 0.3.3 (4.2) | Да, аддитивно в 0.3.3 (по pub-конвенциям для 0.x допустимо; необходимо для полного фикса B5) |
