# Конвенции проекта

Правила, по которым тут пишут код, тесты, документы и релизы. Устройство
пакета — в `docs/architecture.md`, текущее состояние — в
`docs/handoff.md`.

## 1. Язык

| Где | Язык |
|---|---|
| общение с владельцем | русский |
| `AGENTS.md`, `docs/*.md`, `docs/records/` | русский |
| `README.md`, `CHANGELOG.md` | английский |

### Перевод README

`README.ru.md` — перевод `README.md` для владельца, живущий только
в репозитории: в `.pubignore` он есть, в архив pub.dev не попадает,
и `README.md` на него не ссылается. Правило «правишь оригинал — тем же
коммитом правишь перевод» — в `AGENTS.md` §2. Здесь — как переводить.

- **Структура один в один.** Те же разделы в том же порядке, те же блоки
  кода, те же врезки `> [!NOTE]`/`> [!IMPORTANT]`/`> [!WARNING]`, те же
  внешние ссылки. Расхождение в структуре — признак того, что перевод
  начал жить своей жизнью.
- **Код внутри блоков не трогаем**: имена, строковые литералы, вывод
  в комментариях-примерах (`// [i] package | feature | ...`) остаются как
  в оригинале. Переводятся только пояснительные комментарии
  (`// Меняем паблишер глобально`).
- **Якоря считаем заново.** Заголовки русские, значит и якоря русские:
  GitHub опускает регистр, выбрасывает пунктуацию и обратные кавычки,
  пробелы заменяет на дефисы: заголовок «Почему не просто `if (logging)`?»
  даёт якорь `#почему-не-просто-if-logging`. Внутренние ссылки после
  правки заголовка нужно чинить руками — сломанный якорь молчит.
- **Термины — как в `docs/`**: логгер, уровневый логгер, саблогер,
  паблишер, трансформер, форматтер, отложенные вычисления, флаг связи.
- **Ширина 80**, как и во всех остальных markdown-документах. Длиннее
  остаются только те строки, что длиннее и в оригинале: ссылки, бейджи
  и таблицы.

## 2. Код

Анализатор строгий, и это не декорация: `strict-casts`,
`strict-inference`, `strict-raw-types`, `discarded_futures`,
`unawaited_futures`, `cancel_subscriptions`/`close_sinks` как ошибки.
`dart analyze` должен давать 0 issues.

- **Модификаторы классов обязательны.** Публичные классы объявляются
  как `final`, `base`, `abstract base` или `abstract interface` —
  голый `class` не используется. Расширяемые пользователем базы —
  `abstract base`, конкретные реализации — `final`.
- **Импорты внутри `lib/` — только относительные**
  (`prefer_relative_imports`); импортировать
  `package:logger_builder/logger_builder.dart` из `lib/src/` нельзя —
  это риск цикла.
- **`public_member_api_docs` включён.** Каждый публичный член
  экспортируемого класса — с dartdoc. Файлы в `lib/src/**/internal/`
  не экспортируются и отключают правило файловым `ignore_for_file`.
- **Ширина строки 80** — как форматирует `dart format` по умолчанию.
  Тот же предел держим и в markdown-документах.
- **`@visibleForTesting`** — для членов, которые нужны тестам, но не
  пользователям; в dartdoc прямо пишем «for tests only».
- **TODO в коде — в flutter-стиле** (`flutter_style_todos`), но постоянное
  место для пожеланий — `docs/backlog.md`, а не комментарии.

Дизайнерские инварианты пакета (подмена `_log`/`_noLog` по identity,
`publishLog` вместо прямого `publisher.publish`, fail-closed
трансформеры, контракты `flush`/`close`) описаны в
`docs/architecture.md` — их нельзя ломать «походя».

## 3. Тесты

- Один файл на подсистему, имя — `<подсистема>_test.dart`. Общие
  тестовые логгеры — в `test/utils/`.
- Работаем от красного теста: сначала регресс-тест, воспроизводящий
  дефект, потом фикс.
- Регресс-тест ссылается в комментарии на ID находки из записи в
  `docs/records/` (например, `// B1`, `// CR6`) — чтобы через полгода
  было понятно, что именно он стережёт.
- Асинхронные сценарии проверяем детерминированно (тестовые хуки вроде
  `pruneSubloggers()`), а не через ожидание сборщика мусора или таймеры.

## 4. Проверки

```sh
dart analyze
dart test
dart format --output=none --set-exit-if-changed .
```

Все три обязаны быть зелёными до коммита. `dart analyze` из корня
захватывает и `example/logger_builder_examples/` — предупреждения там
роняют CI (`.github/workflows/dart.yml`) так же, как в `lib/`, потому что
`dart analyze` считает warning фатальным.

**Ловушка при тестах на рекурсию.** Если тест роняет изолят по Stack
Overflow, `dart test` не падает, а виснет молча и навсегда: ни вывода,
ни срабатывания `--timeout` (синхронную рекурсию нечем прервать). Так
теряется единственное, что важно, — сообщение о падении. Поэтому такие
тесты гоняем с редиректом в файл и внешним сторожевым таймером:

```sh
(dart test > out.log 2>&1) & P=$!
for i in $(seq 1 60); do kill -0 $P 2>/dev/null || break; sleep 1; done
kill -9 $P 2>/dev/null; pkill -9 -f 'test.dart-'
head -40 out.log
```

Пайп в `tail`/`grep` здесь не годится — при убийстве процесса буфер
теряется и вывод пропадает целиком.

## 5. Git

- Мержим прямо в `main`, без PR.
- Не смешивать свои правки с чужими: перед коммитом смотрим
  `git status` и `git diff`, коммитим только своё, о чужом сообщаем
  владельцу.
- Сообщение коммита — по-английски, повелительное наклонение,
  первая строка — суть правки.
- **Первая строка начинается с префикса** по Conventional Commits:
  `тип(область): суть`. Область необязательна, суть — с маленькой буквы,
  без точки в конце (`fix(multi_publisher): isolate publisher errors`).
- Релизный коммит называется `Release X.Y.Z` и тегируется `vX.Y.Z`. Это
  **единственное исключение** из правила о префиксах, по решению
  владельца: релизный коммит ищут глазами в `git log`, и он должен быть
  виден с первого символа строки.

Типы:

| Тип | Когда |
|---|---|
| `feat` | новая возможность пакета |
| `fix` | исправление дефекта |
| `perf` | производительность без изменения поведения |
| `refactor` | правка кода, не меняющая ни поведения, ни API |
| `docs` | `README*`, `docs/`, dartdoc, комментарии |
| `test` | только тесты |
| `build` | `pubspec.yaml`, зависимости, версия |
| `ci` | `.github/workflows`, `.pubignore`, `analysis_options.yaml` |
| `style` | форматирование, без смысловых правок |
| `chore` | всё остальное: релизы, служебные файлы |

Ломающее изменение — восклицательный знак перед двоеточием
(`feat(logger)!: ...`), и оно же помечается в `CHANGELOG.md` как
`[breaking changes]`.

Тип называет **природу правки, а не задетый каталог**. Правка в `lib/`
ради формулировки в dartdoc — это `docs`, а правка в `test/`, чинящая
ложно-зелёный тест, — это `fix`. Коммит, который не удаётся назвать одним
типом, обычно надо разделить на два.

Префиксы введены 2026-08-17 по решению владельца, и семь коммитов того же
дня переименованы задним числом, чтобы правило не начиналось с пробела.
Действует с `75ddc17`; всё, что старше, префиксов не имеет.

## 6. Версионирование

Пакет в зоне `0.x`, где по конвенциям pub `^0.5.0` означает
`>=0.5.0 <0.6.0`:

- **минорный бамп** (`0.5.0` → `0.6.0`) — breaking-изменения;
- **патч** (`0.5.0` → `0.5.1`) — совместимые.

Аддитивное (новый опциональный именованный параметр, новый член класса)
допустимо в патче. Всё, что меняет наблюдаемое поведение корректного
пользовательского кода, — только в минорном бампе.

Удаляемое API сначала получает `@Deprecated`-мостик в предыдущем релизе
(как `HasFlush` → `Flushable`).

## 8. Что не публикуется

`.pubignore` замещает `.gitignore` при публикации, поэтому записи
`.gitignore` в нём продублированы. Внутренние рабочие документы
(`AGENTS.md`, `CLAUDE.md`, `docs/`) в пакет не попадают — при
добавлении новых внутренних файлов в корень их нужно туда же вписать.

Там же `README.ru.md`. Это рабочая копия владельца, и `README.md` на неё
**не ссылается** — намеренно, по его решению. Значит, публикуемый README
о существовании перевода не знает, и добавлять туда указатель не нужно.

## 9. Документы

- `docs/handoff.md` — только текущее состояние. Без пересказа истории
  коммитов, без разбора законченных эпизодов, без пожеланий владельца.
- `docs/backlog.md` — пишет только владелец; агент оттуда удаляет
  сделанное.
- `docs/architecture.md` — то, что меняется редко.
- `docs/records/` — история: `YYYY-MM-DD[N]-name-kind.md` с шапкой
  «Состояние / Что это / Связанные записи». Полное описание правила —
  в `AGENTS.md`.
