## Открытые вопросы

1. **Job `oldest-supported` в CI не проверен локально.** Он ставит SDK
   3.6.0, которого на машине нет. Первый прогон CI подтвердит или
   опровергнет. Если упадёт — смотреть на разницу в наборе линтов старого
   анализатора.
2. **`maxBufferSize` и политика сброса не вводились** (см. вердикт по
   M10). Очереди по-прежнему неограниченны, это описано в dartdoc. Форму
   API стоит обсудить отдельно.
3. **Подъём SDK и переход на `lints 6.x`** не делались: при `sdk: ^3.7.0`
   и выше `dart format` переформатирует 38 файлов из 45 (замерено). Нужен
   отдельный коммит «Reformat for the 3.7+ style», иначе диффы утонут.
4. **У волны 0.5.0 нет записи в `docs/records/`.** Что вошло, видно по
   `CHANGELOG.md` и коммитам `313e3f0..89730fb`.

## Если сессия оборвалась здесь

Волна 1 закоммичена целиком, дерево после неё чистое. Продолжать с волны 2
(P1) по плану в конце записи ревью. Вердикты по закрытым находкам стоят
отдельными абзацами в самой записи — по ним видно, что уже сделано, не
перечитывая диффы.

Одно решение волны 1 стоит знать до продолжения: `H5` закрыт
документированием, а не симметрией с `format`. Автоматический ретрай всего
батча при бросившем `output` заменил бы тихую потерю на тихое дублирование,
потому что сток мог уже принять часть батча. Если владелец решит иначе —
это меняет контракт, а не только код.

Что стоит перепроверить перед любым следующим действием, по `AGENTS.md`
§1: `git status --short` должен быть пуст, а на вершине `git log` —
коммит «Refresh the handoff for a possible restart», под ним `f01373e`
и четыре коммита волн из таблицы выше. Если расходится — верить git и
приводить этот файл в соответствие.

проверялись находки ревью, жили в скретчпаде сессии вне репозитория и не
