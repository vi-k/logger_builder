## Для независимого ревью

**Что ревьюить.** Предмет — неопубликованная дельта 0.5.0 → 0.5.1:

```sh
git diff v0.5.0..HEAD -- lib test example README.md CHANGELOG.md
```

Это ~60 строк в `lib/`, ~220 строк тестов и ~330 строк README. Вся
дельта — про трансформеры логов плюс документация. Остальная кодовая
база не менялась с релиза 0.5.0 и проходила кросс-ревью на 0.4.0
(`2026-07-29[1]`, `[3]`, `[4]`).

**Где смотреть в первую очередь:**

- `lib/src/custom_logger/custom_level_logger.dart` — `publishLog`, guard;
- `lib/src/custom_logger/custom_logger.dart` — поле `_transforming`;
- `lib/src/async_publishers/transform_publisher.dart` — второй guard;
- `test/transformer_test.dart`, `test/transform_publisher_test.dart` —
  8 новых тестов.

**Осознанные решения (не находки, а выбор):**

- Guard — флаг на экземпляре, а не статический на библиотеку.
  Статический ловил бы больше, но запрещал бы законный случай:
  логирование из трансформера в посторонний логгер со своим
  трансформером. Обоснование — в записи `2026-08-16[2]`.
- Флаг снимается **до** передачи лога паблишеру, иначе цепочка
  «трансформер логгера → `MultiPublisher` → `TransformPublisher`» читалась
  бы как реентерабельная. На это есть тест.
- Реакция на реентерабельный вызов — fail-closed: вложенный лог
  отбрасывается, в зону/`onError` уходит `StateError`. Симметрично
  поведению бросающего трансформера.
- `CustomLog.zone` по-прежнему не используется библиотекой — решение Р6
  из `2026-07-29[2]`, не недосмотр.

**Известные пределы guard'а:**

- Ловится любой цикл, возвращающийся к логгеру, чей трансформер уже
  выполняется, — в том числе через несколько логгеров (есть тест).
  **Не** ловится бесконечная цепочка всё новых экземпляров логгера
  (например, трансформер, создающий саблогер на каждый вызов).
  Признано патологией и не закрывалось.

**Открытый вопрос к ревьюеру.** Паблишер, логирующий в свой же логгер,
рекурсирует до `StackOverflowError` — guard'а на этом пути нет (замерено:
2178 вызовов). Это не регрессия, так было всегда. Асимметрия
задумывалась так: рекурсия через трансформер была тихой (тысячи
опубликованных дублей, а иногда мёртвый изолят без внятной причины),
а рекурсия через паблишер громкая — `StackOverflowError` вылетает прямо
из места вызова логирования. Стоит ли закрывать и её — вопрос открытый.
